# 设计哲学

## 前言

暖暖框架的理念是「数据驱动工作流」。

技能系统的底层逻辑——资源管理、冷却控制、现场清理、UI 交互——全部由框架接管。Mod 开发者只需通过配置表（defs）声明设计内容，不需要处理这些实现细节。

**配置即设计**：你声明什么，框架就执行什么。


## 设计思想

这套设计思想源于我在开发暖暖 Mod 时的实践。用具体例子来理解会更容易。

暖暖 Mod 有多套服装，穿上后赋予角色不同能力。以最初的两套为例：

- **轻盈泡泡**：移速 ×120%，赋予跳跃能力
- **纯净之风**：伤害 ×120%，赋予发射净化弹的能力

> **State 就像你穿的「套装」，换上它就换了一套能力组合。** 跳跃或净化弹是「主动技能」，移速或伤害加成是「被动光环」。

这两套服装代表了不同的**状态**——轻盈泡泡偏探索，纯净之风偏战斗。于是有了第一个概念：

**State（状态）**：一组能力的集合。

接着看「轻盈泡泡」的两项能力：移速 ×120% 和 赋予跳跃能力。

- **移速变化**：被动能力，长期存在，持续影响角色
- **跳跃**：主动能力，玩家选择时机，瞬间触发

> **Effect 是「Buff / 被动技能」，挂上后持续生效；Skill 是主动技能，只在瞬间触发效果。**

核心区别在于**时间**。由此抽象出两个概念：

**Effect**：持续影响的能力。
**Skill**：瞬间影响的能力。

随之而来的问题是：**Skill 要在哪个瞬间触发？** 于是引入：

**Trigger（触发器）**：触发 Skill 的手段。

支持按键（keys）、事件（events）、动作（actions），以及轮盘（wheel）等多种方式。

> **Trigger 就是「扳机」，决定了按什么 / 发生什么时，技能会被触发。**


## 总结

| 概念 | 一句话解释 | 形象理解 |
|:---|:---|:---|
| **Effect** | 持续影响的能力 | 被动 / Buff |
| **Skill** | 瞬间影响的能力 | 主动技能 |
| **State** | 能力的集合 | 切换形态 |
| **Trigger** | 触发 Skill 的手段 | 技能「扳机」 |

以上就是框架的四个核心概念，也构成了配置表的基础。
